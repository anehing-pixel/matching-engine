## 3. 测试没覆盖的地方（诚实清单）

| 缺口 | 风险 | 补救 |
|---|---|---|
| 随机组合下的不变量 | 手写场景无法覆盖未知组合 | 02 §F-04 proptest |
| 反序列化恶意输入 | 畸形数据可能 panic | fuzz（cargo-fuzz） |
| 跨进程/断电恢复 | 只测了"流程"，没测真实 kill | 混沌测试（kill -9 注入） |
| 高频并发下的事件顺序 | 单线程模型下风险低 | 压测时验证事件序号单调 |
| 资金费率、条件单等未实现项 | 无测试（功能也没有） | 随功能开发同步补 |

## 4. CI 质量门禁

```bash
# 每次提交必须全部通过
cargo fmt --check                     # 格式
cargo clippy --all-targets -- -D warnings   # lint（零警告）
cargo test                            # 单元 + 集成
cargo build --benches                 # 基准可编译

# 每周/发布前
cargo bench --bench matching          # 与基线对比，回退 > 20% 阻断
```

### 4.1 为什么把 clippy 提升到 `-D warnings`

这个项目当前是零警告状态。一旦允许警告存在，就会逐渐积累到"警告墙"，
没人再看警告，真正的隐患被淹没。**保持零警告是一个低成本的长期收益**。

### 4.2 基准回归的判定

```
基线：place_resting/10000  median ≈ 5.6 ms
阻断阈值：> 6.7 ms（+20%）
注意：不同机器不能直接比较绝对值，CI 上要用同一台 runner
```

## 5. 编写新测试的规范

1. **一个测试只验证一条规则**，名字写清"验证什么"，不写"测试1"。
2. **优先断言业务结果**（成交价、成交量的序列），而不是内部字段。
3. **失败信息要有用**：`assert_eq!(trades, expected)` 比 `assert!(ok)` 好一百倍。
4. **不要依赖外部环境**：测试用 `temp_dir()/独立子目录`，并在结尾清理。
5. **确定性**：需要随机时用固定种子（见 `Lcg` 实现），不要引入 `rand` 的不确定种子。
6. **跨度覆盖**：涉及持久化的测试必须覆盖"有快照"和"无快照"两条路径。

## 6. 混沌演练清单（季度）

| 演练项 | 做法 | 通过标准 |
|---|---|---|
| 撮合进程 kill -9 | 压测中随机 kill | 重启后盘口与 kill 前已确认状态一致 |
| 磁盘写满 | 填充磁盘 | 明确报错并停止接单，不产生脏数据 |
| 磁盘延迟注入 | 用工具给 WAL 目录加 100ms 延迟 | 延迟上升但不丢数据、不乱序 |
| Kafka broker 挂 | 停掉一个 broker | 消费恢复后无重复结算（靠 seq 幂等） |
| 从零恢复 | 只留备份，干净机器恢复 | 盘口与终态一致，耗时 < 10s/10 万挂单 |

## 7. 测试代码的组织

| 位置 | 放什么 |
|---|---|
| `src/*.rs` 内 `#[cfg(test)] mod tests` | 模块内私有逻辑（当前未使用，可后续补充） |
| `tests/*.rs` | 公开 API 的行为测试（当前 28 个都在这里） |
| `benches/*.rs` | 性能基准 |
| `tests/prop_*.rs`（计划） | 属性测试 |

**为什么当前把测试都放 `tests/`**：这些都是"从外部视角验证行为"的测试，
放在集成测试位置更贴切；模块内部实现的测试（如果以后有）才放进 `src/`。
